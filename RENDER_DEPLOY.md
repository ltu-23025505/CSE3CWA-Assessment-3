# Render deployment runbook

AI Capsule deploys to Render as a single free web service. Render builds the React app, then runs
Express, which serves both the API and the built frontend from one origin — so there is no CORS and
the session cookie stays same-origin.

Budget about 20 minutes, plus a few minutes for the first build.

**One thing to read before you start:** on Render's free plan the filesystem is **ephemeral**. The
SQLite file is erased whenever the service restarts, redeploys, or spins down after 15 minutes idle.
That is expected and is documented in the README as the application's honest limitation. Create a
record during the video so the marker sees real data.

## 1. Create the service

### Option A — blueprint (recommended, uses `render.yaml`)

1. Sign in to `dashboard.render.com`.
2. **New → Blueprint**.
3. Connect GitHub and pick **`ltu-23025505/CSE3CWA-Assessment-3`**.
4. Render reads `render.yaml` and shows the service it will create. It will ask you to enter the two
   `sync: false` values (`GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`) — paste them in.
5. **Apply**.

`JWT_SECRET` is generated by Render automatically, so you never handle it.

### Option B — manual web service

1. **New → Web Service** → connect the repository.
2. Fill in:

| Field | Value |
|---|---|
| Name | `cse3cwa-a3-ai-capsule` → becomes `https://cse3cwa-a3-ai-capsule.onrender.com` |
| Region | **Singapore** (closest to Australia) |
| Branch | `main` |
| Runtime | **Node** |
| Build Command | `npm run build` |
| Start Command | `npm start` |
| Instance Type | **Free** |
| Health Check Path | `/api/health` |

3. Add the environment variables below, then **Create Web Service**.

## 2. Environment variables

**Environment** tab → add these:

| Key | Value |
|---|---|
| `NODE_VERSION` | `22` |
| `NODE_ENV` | `production` |
| `JWT_SECRET` | click **Generate** (Render creates a long random value) |
| `GITHUB_CLIENT_ID` | your OAuth App client ID |
| `GITHUB_CLIENT_SECRET` | your OAuth App client secret |

**Do not set `DATABASE_PATH`.** It is intentionally left unset so the database falls back to
`backend/data/capsules.db` inside the service directory. That path is writable, but ephemeral.

`NODE_ENV=production` is what makes the session cookie `Secure`. Render sets `PORT` itself and the
server reads it.

## 3. Wait for the first deploy

Watch the **Logs** tab. A successful build ends with something like:

```
==> Running 'npm start'
AI Capsule listening on port 10000
  database: /opt/render/project/src/backend/data/capsules.db
  mode:     production (Secure cookies)
```

If instead you see the pages 404 but `/api/health` works, the frontend build did not run — check the
log for the `npm run build` step and send it to me.

## 4. Register the production callback URL

The OAuth callback URL is derived from the incoming host, so Render needs no extra setting — but
GitHub must be told to accept the Render hostname.

**GitHub → Settings → Developer settings → OAuth apps → AI Capsule → Edit**:

- **Homepage URL**: `https://cse3cwa-a3-ai-capsule.onrender.com`
- **Authorization callback URL** — click **Add callback URL**, keeping the existing one:

```
http://localhost:5173/auth/github/callback
https://cse3cwa-a3-ai-capsule.onrender.com/auth/github/callback
```

Update the application. **Leave wildcard matching disabled** — exact matching only.

## 5. Verify the deployment

```bash
APP=https://cse3cwa-a3-ai-capsule.onrender.com

curl -i $APP/api/health
# expect: HTTP/2 200   and   {"status":"ok"}

curl -i $APP/api/capsules
# expect: HTTP/2 401   and   {"error":"Unauthorized"}       <- Test 1

curl -i -H "Cookie: token=fake-token-123" $APP/api/capsules
# expect: HTTP/2 401   and   {"error":"Unauthorized"}       <- Test 2
```

Then in a browser:

1. Open `$APP` — the landing page loads over HTTPS and the URL is **not** localhost.
2. **Continue with GitHub** → authorise → you land on `/dashboard`.
3. **Create a capsule now**, and leave it in place for the video.
4. Edit it, then delete it and create a fresh one to leave behind.
5. Sign out, then open `$APP/dashboard` directly — you are sent to `/login`.

If sign-in succeeds but every API call returns 401, the cookie is not being accepted: confirm the URL
is `https://` and that `NODE_ENV` is `production`.

## 7. Free-plan behaviour to expect

| Behaviour | Detail |
|---|---|
| **Spin down** | After 15 minutes with no traffic the service sleeps. The next request takes about a minute to wake. The brief explicitly allows this. |
| **Ephemeral disk** | The SQLite file is erased on restart, redeploy and spin-down. The dashboard will be empty after a cold start. |
| **Instance hours** | 750 free instance hours per month per workspace; a spun-down service does not consume them. |
| **Warm-up before recording** | Open your URL once a minute or two before recording so the instance is already awake. |
